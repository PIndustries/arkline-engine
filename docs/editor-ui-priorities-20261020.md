Grounding: the actual supplied2048x1230 `.11` mining screenshot (Library `libfile_3d9109b2726c8191b6af6f51e2fd933a`) and2048x1323 `.12` screenshot (`libfile_dbfebd2aa55c8191891e3dc74f0f8c3f`) were retrieved and viewed. ## Critical scope in the current candidate

1. **World first during flight.** Default Flight focus uses the existing editor viewport, hides authoring sidebars and scene-placement row, and retains an immediate Editor switch. Models, Mining, Sound and Session stay accessible. Editor restores the existing authoring navigation and panel hierarchy; no capability or framework is removed. Toggling focus is tested to leave the paused authority snapshot unchanged.
2. **Essential instruments low and to the sides.** One shared physical cockpit recipe fits all five faces, lowers the central status screen into the bottom instrument band, connects its supports, and refits the exact identified source diagonal into a real perimeter post. Same eye/FOV/geometry in docked and flight views; rear-chair path and boarding supports stay intact. Original GLB and inspection buffers remain original. Three-aspect full-face and exact ray guards are supplemented by native five-drone/split-feed captures and actual packaged-window checks.
3. **Management is deliberate.** Default central display is a compact flight/mining status page; it is not the full Mining/Drones/Spark form. Flight/Drones/Mining buttons open normal-size panels. Console pages is an explicit focused mode, with Flight view to return. Focused physical input/typing remains covered separately. Existing optional expanded panels are reused rather than adding a new panel system.
4. **Immediate legibility.** Smaller logical canvas, explicit instrument type scale, no wrapped Mining label in a28px rail, and no duplicated top-left location text. This does not certify readability at arbitrary window sizes; actual user viewport/chrome must be observed before declaring the cutoff repaired.

## Next critical usability pass, after this bounded delivery

- Group navigation by intent: Flight/Mining/Drones/Cargo for operating; Models/Rooms/Materials/Equipment for editing; Git/Files/diagnostics under authoring. Inventory exact existing routes before changes and keep a visible way back to Flight. Avoid another row of undifferentiated controls.
- Establish one readable type/spacing scale for normal panels: clear title, primary action, grouped secondary controls and concise status. Dense telemetry belongs in explicit inspection, not the default flight view. Validate logical and physical pixels in the actual window, including compact widths and long labels.
- Normalize panel behavior: explicit open/close/focus, predictable scroll ownership and no covered primary controls; retain existing keyboard and pause/input boundaries. Test switching Flight/Editor, Mining, Models and Sound with unsaved edits and active work.

## Later polish

Consistent icons/material language, restrained accent use, aligned sections and better empty-state copy follow the information hierarchy. Additional trim, lighting or decorative machinery does not repair the reported visibility/navigation failures. Overall flagship art completion and whole-UI acceptance are not claimed by this candidate.
