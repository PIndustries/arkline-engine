# Source-bound physical cargo inspection

This opt-in inspection milestone uses the existing server ownership lock, `world`
JSON row, `ledger` table, `LedgerEntry` hash envelope and atomic transaction helper.
It is not a second independently deployed authority. Its dedicated wrapper does
not expose normal gameplay transport, and normal `Server::open` refuses its stamp.
Legacy worlds are never migrated or assigned physical-volume balances.

The protocol source registry binds the final 1704 geometry configuration and its
94 mm receiver-panel motion contract. It derives capacity from the source-certified
cells: 214,121,238 cm³ for the ship and 893,833 cm³ for the mining drone. Source,
GLB, geometry proofs and motion receipts retain their exact independent hashes.
The registry pins external assets; loading a real asset still requires checking
its actual bytes. The configuration does not admit a changed collision shape by
pretending it is the previous 1703 runtime geometry.

A fresh inspection genesis explicitly supplies material identity, authored rates,
finite resource volume and at most twenty finite mining drone identities. There
are no default rates, prices, density or engineering ratings. Rate fixtures are
accounting inputs, not measured pump performance. Energy quantities retained in
the catalog are authored design information; this accounting inspection does not
claim to debit a physical power system or establish extraction contact.

The server uses the shared `PhysicalCargoAccount` integer primitives for balance
changes. The verifier separately reconstructs ruleset-4 events without invoking
those transitions. Claims reserve capacity and finite source volume, extraction
has an explicit deadline, and one shared manifold service enforces batch and time
limits. Holds stop transfer. Restart cancels pending claims and holds any active
service through the ledger rather than processing catch-up. An exact retry returns
the original transfer result without another ledger event or debit. Source,
roster, quantity, history, timestamp and account mismatches reject before commit.

The next adapter must bind this accounting boundary to actual new-source drone
mining contact, power, receiver seating, both valves, continuous transfer path,
identity, damage and cancellation. Its controller events are currently inspection
inputs, not evidence that a drone is physically docked. Concurrent reload, return,
warp, native UI and ordinary gameplay admission remain separate acceptance gates.
Nothing here converts old prototype units or publishes a build.
