# Physical-source 1704 inspection compiler

This is a **new** source-bound provider, not a widened 1703 match. The first
bounded fixture exposes only Mining, initial cassette 0, bay 0 launch/capture and
an explicitly typed geometric service sequence. Other classes/bays/identities are
future proof scope, not a proposed permanent gameplay restriction. All twenty
identities and ten ready positions remain in its topology. Stage, generic ore
service, production lookup and travel envelopes remain unavailable.

`../build_physical_provider_fixture.py` takes the final physical proof root,
original exact 1703 export/turret-envelope evidence/GLB and archived source-bound
service poses. It refuses mismatched source bytes and existing output directories.
The common constructor only extracts the same authored transforms and ownership;
the emitted source revision, all collision leaves and complete provenance are new.
The original compiler's default remains 1703.

New receiver occupied material is `union(outer_boxes) - union(void_boxes)` on actual
float32 coordinates. Retained nominal logical boxes are reconciled against actual
exported triangles **within the same rigid root and render batch**. Measured
rounding differences grow conservative collision proxies; no obstacle is shrunk.
An additional outward float32 ULP and bounded float64 transform guard cover
representation arithmetic. Large source/mapping differences are rejected rather
than converted into huge proxies. This guard has no effect on counted storage.

`../check_physical_provider_coverage.py` verifies every actual exported dynamic
triangle against the **serialized runtime local cell union**. Unresolved cases use
exact rational triangle-minus-union clipping, not vertex-only containment. The
negative fixture of three vertices in disjoint boxes rejects the uncovered
triangle between them. An independent route proof uses these expanded proxies.

The 15-frame typed service sequence seats and latches the exact receiver first,
opens the drone inlet by 250 mm, then the ship split valve by 94 mm, reaches a
stable dual-open barrier, closes ship then drone valves, releases, withdraws and
stows before departure. It is geometric inspection, **not transfer authority**.
`physical_inspection_service_route` carries the otherwise missing donor valve
state. Generic `ReturnToUnload` and `supports_ore_service` remain closed for 1704.

This fixture does not register a server world or reuse the old fixed drone body
bounds. Actual new-source motion/service adapters, concurrency, all identities,
power/contact/death accounting, moving-ship/warp, renderer and native acceptance
remain subsequent gates. Frozen unrelated host mechanisms and the inherited
10 micrometre handling contact boundary in offline route screens are explicit
limitations, not engineering ratings or an exact zero-penetration claim.
